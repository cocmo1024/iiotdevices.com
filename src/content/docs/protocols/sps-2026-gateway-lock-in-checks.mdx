# SPS 2026 Preview: Gateway Lock-In Checks for Nuremberg

SPS — Smart Production Solutions is the automation industry's main autumn meeting point, and the 2026 edition lands at a useful moment for anyone buying connectivity hardware. Open standards such as OPC UA and MQTT/Sparkplug have reduced protocol lock-in at the wire level. They have not removed lock-in. It has moved one layer up, into the edge gateway: the protocol mapping rules, tag naming, scaling, and northbound models that a single vendor's configuration tool creates — and that often only that tool can read back.

That is the lens this preview uses. If your SPS 2026 trip includes gateways, protocol converters, or edge devices for brownfield data collection, the valuable output is not a bag of datasheets. It is a set of verified answers to one question per vendor: **if we replace this gateway in five years, what happens to the mapping work we did on day one?**

## Quick answer

Go to SPS 2026 with a mapping checklist, not a protocol checklist. Almost every gateway on the floor will claim Modbus, OPC UA, and MQTT support. The differences that decide long-term cost are whether the protocol mapping configuration can be **exported in a readable form**, whether the mapping rules are **documented**, whether the configuration survives a **vendor change or a tool change**, and how the vendor handles **firmware updates and vulnerability reporting** under the EU Cyber Resilience Act (CRA). Ask those four things at every booth, write the answers down, and treat anything that is not later confirmed in a manual or official document as unverified.

Second, the industrial AI program matters to gateway buyers for a less obvious reason: AI and analytics projects consume modeled, documented data. A gateway whose mappings are undocumented exports that documentation debt into every downstream project.

## Why gateway lock-in is the right SPS 2026 question

A protocol converter used to be a dumb pipe: registers in, registers out. A modern IIoT gateway is where brownfield meaning is created. It decides tag names, engineering units, scaling, deadbands, timestamps, store-and-forward behavior, and how southbound Modbus, serial, or PLC data becomes a northbound OPC UA model or MQTT/Sparkplug topic tree.

That makes the gateway the new lock-in point in three specific ways:

1. **Mapping lock-in.** The translation rules live in a proprietary project file or a vendor cloud account. Export, if it exists, may be a binary backup that only the same tool — sometimes only the same version — can restore.
2. **Semantic lock-in.** Even when raw data can be re-read by a replacement device, the naming, units, and state logic built on top of the first gateway's tooling have to be rebuilt and re-validated by hand.
3. **Lifecycle lock-in.** Firmware updates, security patches, certificate handling, and license terms decide whether the device can stay in service through the CRA era. A gateway that cannot be patched economically is a scheduled replacement, not an asset.

None of this is visible in a protocol support matrix. It is visible in answers to the checklist below — which is why a trade show, where engineering staff are on the booth, is a good place to ask.

## The booth checklist: protocol mapping questions that separate vendors

Ask these in order. The first two are the decisive ones; the rest price the risk.

| # | Ask at the booth | A strong answer sounds like | A weak answer sounds like |
| --- | --- | --- | --- |
| 1 | Can the full protocol mapping configuration be exported from the device or tool — in what format? | A readable, documented export (for example structured text/XML/JSON/CSV) that a replacement workflow can consume | "You can back up the project" with no readable format, or export only into the vendor's cloud |
| 2 | Is the mapping format documented — publicly, or only under NDA/support contract? | A public manual or document describes the export format and the mapping model | The format is "internal"; documentation is promised after purchase |
| 3 | If we replace this gateway with another brand, what exactly must be rebuilt? | A concrete list: mappings re-entered or imported, certificates re-issued, topics renamed — with effort the vendor can describe | "That never happens" or a migration offer priced later |
| 4 | Can the device be configured fully offline, without a vendor cloud account? | Yes, local tool or web interface, no account dependency for core configuration | Configuration, licensing, or backups require the vendor's portal |
| 5 | How are tag names, units, scaling, and timestamps represented in the export? | Semantics travel with the export, not only raw addresses | The export holds addresses; meaning lives in a separate, manual document the plant must maintain |
| 6 | Northbound: can the same mapping feed OPC UA and MQTT/Sparkplug without duplicate configuration? | One mapping model, multiple publishers | Each northbound protocol is a separate hand-built configuration |
| 7 | CRA readiness: what is the committed firmware support period, and how are vulnerabilities reported and patched? | A stated support period, a published vulnerability disclosure channel, signed updates | "We take security seriously" with no period, no channel, no update mechanism |
| 8 | What happens to configuration and licenses if the vendor discontinues the product line? | Documented end-of-life and migration policy | No policy the booth team can point to |

Score the answers immediately, on the floor. Booth memory degrades fast across three days and around 1,180 exhibitors.

## How this site will score the answers: the December device database rule

This checklist is not only show advice. From its first build batch on 2026-12-05, the device database on this site records a fixed field for every gateway and protocol converter:

**Protocol mapping exportable and documented? — yes / no / vendor undeclared.**

The field is judged only from vendor manuals and official documentation, never from booth conversations, sales material, or this preview. A vendor whose SPS answers sound strong will still be recorded as "vendor undeclared" until the export format appears in their own documentation. ## FAQ

**When and where is SPS 2026?**
24–26 November 2026 in Nuremberg, Germany — the 35th edition of SPS — Smart Production Solutions, organized by Mesago Messe Frankfurt, with around 1,180 exhibitors expected.

**What are the main topics at SPS 2026?**
According to the organizer, the agenda focuses on industrial AI in practical use and on implementing the EU Cyber Resilience Act (CRA), including around 30 expert presentations and panel discussions on industrial AI.

**What is gateway lock-in?**
It is the dependence created when a gateway's protocol mapping rules, naming, and configuration live in one vendor's tooling or cloud, in formats that cannot be exported readably or are not documented. The protocols may be open while the mapping work is not portable.

**What is the single most useful question to ask a gateway vendor at SPS 2026?**
"Can the full protocol mapping configuration be exported in a readable, documented format?" Followed by: "Show me where that format is documented." Those two answers predict replacement cost better than any protocol support matrix.

**Why does the CRA belong in a gateway purchasing checklist?**
Because reporting duties already apply (since 11 September 2026) and the CRA becomes fully applicable on 11 December 2027. A connected gateway's firmware support period, update mechanism, and vulnerability handling decide whether it can stay in service compliantly — so they are selection criteria now, not afterthoughts.

**Will this page name the best gateway from SPS 2026?**
No. This preview sets the checks. Product-level findings belong in the device database from December, where the mapping field is recorded only from vendor documentation.
